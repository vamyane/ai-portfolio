## 一、它想验证什么

公众号排版有两个绕不过去的老问题：

1. **模板都长得差不多。** 市面上的模板库大多是「换了个颜色」就算一套新模板，用起来同质化严重。
2. **排好的版一粘贴就废。** 在编辑器里好看的样式，复制进公众号后台经常丢一半——阴影没了、间距崩了、字体变了。

这个 Demo 就是拿来做一次验证：**能不能用一套更聪明的模板结构，同时解决这两个问题。**

## 二、核心设计思路（这才是重点）

### 思路一：模板 = 色板 + 结构组件，而不是一张写死的样式表

传统做法是「一个模板 = 一份完整的 CSS」，所以加一套模板就要写一份新样式，模板越多越难维护。

这里的做法是把模板拆成两层：

- **色板（palette）**：每个模板只定义主色、文字色、背景色、字体这几项，引擎**自动派生整套色阶**（深色 / 浅色 / 柔和底 / 渐变搭档）。
- **结构组件库（style library）**：标题、引用、列表、分隔线、卡片、段落、图片、整文容器，每一种都有多种**结构变体**——色块条、编号、气泡、胶带、双线……模板通过一个 `style` 字段选择用哪种结构。

模板里所有颜色都用 `{accent}` 这类**占位符**引用色板，而不是写死色值。带来两个结果：

- 用户换一个主色，**整套模板跟着联动**——一套模板 × N 个颜色 = 上百种可用样式；
- 视觉差异化来自**结构**（是色块条还是气泡、是双线还是胶带），而不是只换个颜色，所以模板之间是真的不一样。

### 思路二：为「复制到公众号」这个终点去设计输出，而不是为浏览器好看

这是整个 Demo 里我做得最刻意的一件事。

排版的**终点不是「在编辑器里好看」，而是「粘贴到公众号后台之后还好看」**。所以输出层定了两条硬规则：

- **只用真实元素 + 内联样式**，不用伪元素——微信的编辑器识别不了伪元素，会直接丢。
- **微信会剥离的属性（如 `box-shadow`、`text-shadow`）只在预览里使用**，一旦走复制流程就剥离，并给一个回退的纯色，避免「复制过去变成一块灰」。

换句话说：**预览态和交付态是两套输出**，而不是同一份 HTML 走到底。

### 思路三：把用户的输入门槛降下来

用户面对的是一个富文本编辑器，但排版公众号的人大多数习惯写 Markdown。所以编辑器直接支持简易 Markdown 语法（`#` 标题、`##` 小标题、`>` 引用、`**加粗**`、`---` 分隔线），输入后再解析成结构化内容交给引擎渲染——**用户不用学一套新的编辑方式**。

顺带做了个「智能推荐」：对用户输入的内容做关键词打分（科技/美食/穿搭/旅行等主题各自映射到模板分类），自动挑一档更匹配的模板，省掉在几十套模板里翻找的动作。

## 三、这个 Demo 实现了什么

| 能力 | 说明 |
|---|---|
| 模板库 | 20+ 套差异化模板，按分类筛选 |
| 三段式布局 | 左：模板库 / 中：编辑器 / 右：手机实时预览 |
| 富文本编辑 | 加粗、斜体、删除线、对齐、字号、撤销重做、插入表格 / 图片 / 引用 / 分隔线 / 高亮 |
| Markdown 快捷输入 | `#` / `##` / `>` / `**` / `---` 直接排版 |
| 混搭模式 | 可以为标题、正文、引用等**各部分分别挑不同模板的样式** |
| 智能推荐模板 | 按内容关键词打分自动匹配 |
| 一键复制到公众号 | 写入 `text/html` 剪贴板保留格式；失败降级为纯文本；再失败给手动兜底提示 |
| 颜色自定义 | 自定义主色 / 背景色，模板联动 |

## 四、这个 Demo 的定位与边界

**它是用来验证思路的，不是用来交付的。**

- **它证明了**：模板引擎这套「色板 + 结构组件」的抽象能不能撑起「一模板 × 多色」的联动；「预览态 / 交付态分离」的输出策略能不能解决复制丢样式的问题。
- **它没有做**：后端与账号体系、模板云端同步与用户自定义保存、多浏览器兼容测试、上线部署。

一句话：**它证明的是「这个思路成立」，不是「这个产品可用」。**

## 五、怎么运行

直接双击 `typeset-demo.html` 即可（用到了 KaTeX 的 CDN，需要联网）。

> 文件名没有用 `index.html`，是沿用我自己的命名习惯：网页一律用语义化文件名。

## 六、目录结构

```
typeset-demo.html      页面入口
css/style.css          布局与界面样式
js/engine.js           模板引擎：色板派生 + 结构组件库 + 交付态输出
js/app.js              交互层：编辑器、模板选择、混搭、推荐、复制
templates/             模板定义（每套模板 = 一份色板 + 各组件选用的结构）
preview-1.png          界面预览
```
